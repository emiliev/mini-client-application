# F-0039: McTabBar semantics roles, large-title bands, and what `mc_arch_check` does not enforce

- **Date:** 2026-11-26
- **Author:** crew: Engineer (T-0040)
- **Type:** Gotcha
- **Related:** T-0040-AC1, T-0040-AC2, T-0040-AC3, F-0014, F-0035

## Facts
1. **`SemanticsRole.tabBar` must sit directly above the tabs.** Flutter asserts "Children of TabBar must have the tab role" for every direct semantics child. A `Semantics(role: tabBar)` placed outside a `SingleChildScrollView` fails, because the scrollable's own node is the child. Place it inside the scroll view, around the `Row`, with `explicitChildNodes: true` (Material's `TabBar` does the same). Each tab is `Semantics(role: tab, selected:, button: true, label:, excludeSemantics: true)`.
2. **`flagsCollection.isSelected` is a `Tristate`** (`dart:ui`), not a bool; an unselected tab is `isFalse`, not `none`, when `selected: false` is given.
3. **`AppBar` already marks its title as a semantics header**, so wrapping the title again is redundant. A mutation of such a wrapper survives. The large title is drawn by us, so it carries its own `Semantics(header: true)`.
4. **A fixed-height band hides text-scale overflow.** The large-title `Text` under `Align` in a `SizedBox` gets loose constraints and clamps its height to the band; no overflow error is raised even at 3x, and the glyphs are painted outside. Asserting "no exception" proves nothing. The test reads the `Text.textScaler` instead (capped at `McAppBar.largeTitleMaxScale`, 1.5).
5. **`mc_arch_check` allows utility to utility edges.** Nothing stops `mc_ds_*` from depending on `mc_feature_flow`. T-0040-AC3 enforces it for `mc_ds_navigation` with `tool/checks/T-0040-AC3_layering.sh` (cquery closure, pubspec and import scan, with positive and negative controls). A general rule "`mc_ds_*` never depends on `mc_feature_flow`" belongs in `mc_arch_check` (follow-up).
6. **A scrollable tab bar must reveal the selected tab.** Without it a selected tab can be off screen (five tabs at 2x). `_TabItem` calls `Scrollable.ensureVisible` after the first frame and on selection change (zero duration on first build and under reduced motion).

## Fix round (T-0040, after the Verifier's PASS)
7. **Why the bar stretched.** `Center(widthFactor: 1)` with no `heightFactor` expands to the incoming max height, and a `Scaffold` body is loose with `maxHeight` = the body height, so the tab (and the bar) were 600 pt tall. Fix: each tab is exactly 48 pt (`minHeight == maxHeight`) and the bar is 48 + a 1 pt divider (the `Border` takes no room, so the divider's height is padded in). Because the height is fixed, the label scale is capped at `McTabBar.labelMaxScale` (1.5). The bar is a `PreferredSizeWidget`, so it works in `AppBar.bottom` and `McAppBar.bottom`.
8. **`Scrollable.ensureVisible(context)` scrolls every scrolling ancestor.** A tab bar in a vertical `ListView` moved the whole page on build and on each tab change. The bar owns a `ScrollController` and calls `controller.position.ensureVisible(renderObject)`, which only moves its own row. Reveal runs only when `currentIndex` changes (and on the first build), never on a plain parent rebuild.
9. **Tab widths.** `Expanded` needs a bounded width and `SingleChildScrollView` gives none, so a small `RenderBox` (`_TabRow`) gives each tab its natural width plus an equal share of the free space up to the bar's minimum width. Taps in what used to be gaps select a tab. With an unbounded width (a `Row` without `Expanded`) the bar skips the scroll view (a horizontal viewport cannot be given an infinite width).
10. **Text scale caps (D4, TL decision).** The large title is capped at 1.5x and is single-line with an ellipsis, as iOS truncates large titles too; VoiceOver still reads the full title and the title names the route. Flutter's `AppBar` itself caps the plain title's scale at 1.34x, so the "2x" goldens of the plain bar actually render at 1.34x. Tab labels are capped at 1.5x.
11. **No default leading, loudly.** `McAppBar` cannot default to `McFlowBackButton` (layering). The class comment says that every flow page that can be a flow's root must pass `leading: const McFlowBackButton()`.
12. **A `///` filter hides real imports.** The first layering check dropped any line containing `/// `, so `import 'package:mc_feature_flow/...'; /// x` passed. The check now ignores only whole-line comments, and scans every `mc_ds_*` pubspec and BUILD file, with a negative control for each case.
