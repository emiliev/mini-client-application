# F-0035: `McFlowBackButton` replaces `context.flowLeading()` (T-0036)

Found by the T-0034 Verifier (R2-1), fixed in T-0036, 2026-11-26.

1. **Root cause.** `flowLeading()` was a value computed once in the caller's `build` from `Navigator.maybeOf(this).canPop()`, with no dependency registered. If the root page's `build` ran while an inner page was on top, it got `null` and kept it until something rebuilt the page. A user pop rebuilds the root once (so the stale `null` is recomputed); a **state-driven return** (`controller.update(...)` back to the root, the API a bloc uses) rebuilds nothing, so the button stayed missing. In today's exemplar the bug is **latent, not live**: the preview closes only by a user pop. The bricks will make it live.
2. **Fix.** `const McFlowBackButton()` decides in its own `build`, from `ModalRoute.of(context)`. On the flow's first route: a `BackButton` that pops the flow's outer navigator when it can pop. On any other route: what `AppBar` would show itself, a `DrawerButton` when the `Scaffold` has a drawer, else `BackButton` (`CloseButton` for a fullscreen dialog) when the page can pop. Otherwise `SizedBox.shrink()`. It is therefore safe on every page, which is how the bricks will use it. `flowLeading()` and the `McFlowNavigation` extension are removed (one caller).
3. **Empty slot at the app root (accepted, TL).** When the flow is the app's root and has no drawer, the widget is empty and `AppBar` still reserves its 56 px leading slot. iOS centres titles, so this is the wanted layout; it is documented on the widget and not worked around.
4. **What the AC1 test needs to discriminate.** It must use a **const** root page that rebuilds under the inner page, and it must return with `controller.update(...)`. A page built by a closure or `Builder` is a new widget on every flow state change and is rebuilt on the return, which hides the bug; a user pop (tapping the inner page's back button) rebuilds the root too. Neither alone discriminates; the `controller.update` return does. The kit test reproduces exactly that, and fails with `flowLeading()` (`AC1_negative_control.sh`).
5. **A second defect behind it: the stale `PopScope`.** After `controller.update` returns to the root, flow_builder's `PopScope(canPop: false)` stayed mounted and swallowed the next pop, so the button (and the iOS edge swipe) did nothing: it was visible and dead. Fixed in the vendored flow_builder (patch change 4, F-0034 fact 9). The AC1 tests now tap the button once and swipe from the edge. Re-parenting the navigator when that `PopScope` came and went had also been rebuilding every page, which masked fact 1 in some setups; the scope is now always mounted.
6. **Supersedes** F-0033 fact 7 (`flowLeading()`) and the last sentence of its fact 3 ("With an empty list the flow leaves `Localizations` as the host set it"): the flow is always wrapped in `Localizations.override`, and with an empty list it still adds the core and Flutter delegates the host lacks. `FeatureFlow`'s doc comment is fixed.
7. **Mutation scripts.** `documents/evidence/T-0033/engineer/mutations.sh`: output base and log are named from the required `MC_TASK`/`MC_ROLE`; a non-zero exit with no failing test is `ERROR (no failing test)`, a mutation that fails to build is reported as `COMPILE ERROR` and counts as a failure, and the push-to-go mutation now wraps `go` in `Future<void>.sync`, so it compiles and `universe_wiring:routes_test` kills it.
8. **Scope of the handoff edits.** `tool/checks/T-0035-AC4_gates.sh` no longer runs the lock-delta gate (permanently red after T-0035 merged); `T-0035-AC4_lock_delta.sh` stays as a historical one-off with a "pre-merge only, pinned to 6e7eaaf" header (TL approved).
