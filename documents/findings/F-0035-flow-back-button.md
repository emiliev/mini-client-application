# F-0035: `McFlowBackButton` replaces `context.flowLeading()` (T-0036)

Found by the T-0034 Verifier (R2-1), fixed in T-0036, 2026-11-26.

1. **Root cause.** `flowLeading()` was a value computed once in the caller's `build` from `Navigator.maybeOf(this).canPop()`, with no dependency registered. A const root page that rebuilt while an inner page was on top got `null` and kept it: nothing rebuilds a const page after the inner page pops. In the exemplar the trigger is a locale change with the preview open.
2. **Fix.** `const McFlowBackButton()` is a widget, so the decision is made inside its own `build`. It shows a `BackButton` that pops the flow's outer navigator when `ModalRoute.of(context).isFirst` (its route is the flow's first) and the outer navigator can pop; otherwise `SizedBox.shrink()`. The decision no longer looks at the inner navigator's `canPop`, so a root page that rebuilds under an inner page still has the button once it is uncovered. `flowLeading()` and the `McFlowNavigation` extension are removed (one caller).
3. **Root page only.** On a page pushed inside the flow, do not use it: `AppBar`'s automatic back button pops that page, and a non-null `leading` of `SizedBox.shrink()` would replace it with nothing.
4. **Test trap (the negative control needs a real const root).** `FeatureFlow` regenerates every page's widget on a flow state change. A page built by a closure or `Builder` in `onGeneratePages` is a new widget each time and is rebuilt on the pop, which hides the bug. The AC1 test therefore uses a `const` root page and rebuilds it with its own `ValueNotifier`. It also returns to the root with `controller.update(...)`, not by tapping the inner page's back button; both are real, but only the const-root case discriminates.
5. **Flow history quirk (not changed).** After `controller.update` moves the state back by itself, flow_builder's own history still holds the inner entry, so the first outer pop is consumed to unwind that history and the flow stays. Tapping the flow's back button right after is therefore not asserted in the AC1 test; AC2 covers the tap.
6. **Supersedes** F-0033 fact 7 (`flowLeading()`) and the last sentence of its fact 3 ("With an empty list the flow leaves `Localizations` as the host set it"): the flow is always wrapped in `Localizations.override`, and with an empty list it still adds the core and Flutter delegates the host lacks. `FeatureFlow`'s doc comment is fixed.
7. **Mutation script.** `documents/evidence/T-0033/engineer/mutations.sh`: the log path is task-named (`MC_LOG`, default `/tmp/mc-T-0033-engineer-mutations.log`), a mutation that fails to build is reported as `COMPILE ERROR` and counts as a failure, and the push-to-go mutation now wraps `go` in `Future<void>.sync`, so it compiles and `universe_wiring:routes_test` kills it.
