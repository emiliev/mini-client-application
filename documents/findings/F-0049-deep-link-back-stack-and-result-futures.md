# F-0049: Deep-link back stacks, and a flow result that always completes (T-0049)

## Context
P-087: `/characters`, `/comics/:id`, `/search` and `/me/lists/...` were top-level routes, so a cold link opened a one-page stack with no back button. P-092: after a link replaced an open editor, home's New and Edit buttons stayed dead.

## What we learned
1. **A child's path must be relative; the wiring's typed route is absolute.** go_router asserts that a sub-route's path doesn't start with `/`, but `XRoute(...).location` (and so `AppLocations` and every drift test) comes from the `@TypedGoRoute` path, which a wiring writes in full (`/comics/:id`). The routes can't be declared under `HomeRoute` in the wiring: the typed tree must sit in one library, and a wiring never imports `mini_client`. So `app_core`'s `nestUnderHome(appRoutes, entityRoutes)` copies each generated top-level `GoRoute` with its leading `/` removed (children kept) and adds it under home's route. URLs, `location` and the drift tests don't change. A new wiring joins by adding its route list to the list passed in `buildAppRouter`; a route left outside is a one-page stack when a link opens it, and `deep_link_back_stack_test` (one cold link per entity route) fails.
2. **go_router rebuilds the stack for a link, with `go` semantics.** A link to the running app (`pushRouteInformation`) is a `go`: the stack becomes `[home, target]` (or `[home, list, details]` for `/characters/:id`, which was already nested under the list). Whatever was open before is gone, so Back from the target returns to home, never to the old screen. In-app `context.push(AppLocations.x)` from home still stacks `[home, target]` with home below.
3. **go_router never completes the future of a `push` that a `go` replaced.** The `Completer` lives on the imperative match, which `go` discards. A caller awaiting `GoRouter.push` alone waits forever (this froze home's `_awaiting` guard, P-092). **A result future must always complete; with null when the route goes away.** The fix keeps the future outside go_router: `AppFlows` pushes with a `FlowCall` as the `extra` and returns the call's future, and `FlowResultRoute` (given `extra: state.extra` by the wiring's route) completes it with null in `dispose` if no result came. The result path is unchanged (the pop value completes the call through the push future). The call completes once. A route nobody pushed (a link) has no call and nothing to complete.
4. **A cold-link editor now has a page below it.** The `FlowResultRoute` "first route goes home" branch stays as a safety net, but for linked editors `isFirst` is false now, so completing pops back to home.
5. **Tests gotcha:** home's own button is labelled "New reading list" too, so a finder by that text finds the home button and the editor title. Use the editor's key (`reading_list_editor.details`).

6. **Review round hardening.**
   - The result reaches the call directly in `_deliver` (before the pop), not only through the push future, so it never depends on microtask order (a test pushes the route in a plain Navigator, where only the direct path exists).
   - A route opened through `AppFlows` but built without `extra: state.extra` throws a `FlutterError` in debug builds (`FlowResultRoute._debugCheckCall`, run in `didChangeDependencies` because it reads the route's state). `AppFlows` leaves a token per location; the route takes it.
   - `FlowExtraCodec` (set as `buildAppRouter`'s `extraCodec`) encodes a `FlowCall` as null and decodes it as no call, so go_router neither warns on every push nor tries to save a live future. Other extras pass through (the app uses none).
   - `nestUnderHome` rejects a second route at exactly `/`.

7. **T-0054 hardening (supersedes the location token and the pass-through codec of fact 6).**
   - **One call, one end.** `AppFlows` still pushes a `FlowCall` as the `extra`, but nothing is keyed by location any more. The call ends exactly once, in the first of three ways: the route hands over a result (or its dispose abandons the call); the push's own future completes (a pop, also of a redirected page such as a sign-in, which can pop with a value); or a `go` replaces the pushed page. The third is found by watching `routerDelegate` and looking, after the next frame, for the page whose `ImperativeRouteMatch.completer.future` is the future the push returned (`router.routeInformationProvider.push`, the call `GoRouter.push` makes). That identity is the only handle that survives a redirect: **a redirect drops the push's `extra`** (the redirected match list has `extra == null`), so matching by extra does not work. Listen before pushing: the router can apply a push synchronously.
   - **The guard case (P-094).** `/me/**` signed out: the push is redirected to `/signin?from=...` and the caller waits. Signing in does `go(from)`. The page the guard showed is replaced, so the caller gets null once. The route that `go` builds has no call.
   - **The debug assert** now compares the route's widget `extra` with `GoRouterState.extra`: a `FlowCall` in the state and none in the widget means the route forgot `extra: state.extra`. A route built by a `go` has no call in its state, so it never trips it. (The old per-location token fired on the guard's `go(from)`.)
   - **Held results (P-096).** The route also tells its call what it holds (`FlowCall._hold`) when a result arrives under an overlay. Whatever ends the call later (dispose, or the stack watch, which runs before the route is disposed because a page that a `go` removed under a dialog is disposed late) completes it with that result, not with null. A held result is delivered once.
   - **Extras (P-095).** `FlowExtraCodec` keeps JSON-safe extras (null, bool, finite num, String, List, Map with String keys, to depth 32), drops a `FlowCall` (null), and drops anything else as null with a debug-only warning naming its type, once per type. It never throws. Without a codec go_router throws `JsonUnsupportedObjectError` in the route report on an extra it cannot encode; with the previous pass-through codec every non-JSON extra threw. Rule for picker arguments: **a route's `state.extra` is a JSON-safe value, and null means no argument** (it is null after a restore, and for anything not JSON-safe).
   - **Overlay delivery order.** The result reaches its caller after the overlay closes in either order of "overlay closes" and "`go`". Both orders are tested.
8. **Not found (P-097).** `errorBuilder` made a one-page stack, so a link to an unknown path or a bad id (`/comics/abc`, which throws in the typed route's redirect) had no back button and no way home. Now `onException` (which sees both the no-match and the redirect error) does `go('/not-found?from=<path>')` to a `not-found` route nested under home, so the stack is `[home, not-found]`, cold or running. The page has a back button (pops; goes home when nothing is below) and a "Go home" button. The location shown is the link's path and query, without `miniclient://app`. Gotcha: if the `/not-found` route were ever missing from the routes, `onException` would loop; it is a plain route in `buildAppRouter`, passed through `nestUnderHome`.
9. **Test gotchas.** `debugPrint` replaced in a `testWidgets` must be restored in the test body (tear-downs run after the binding checks its debug variables). go_router logs through `package:logging`'s `logger` (`go_router/src/logging.dart`), not `debugPrint`, so a test that captures it listens to `logger.onRecord`.

## Rule for the bricks
- Every wiring route list goes through `nestUnderHome` in `buildAppRouter`; no entity route is top level.
- A route that ends with a result is built as `FlowResultRoute(extra: state.extra, builder: ...)`, and its caller uses an `AppFlows` entry, which pushes through `FlowCall`.
- A route's `state.extra` is a JSON-safe value or null (null means no argument). Never rely on any other object surviving a saved route state.
