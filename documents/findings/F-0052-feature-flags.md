# F-0052: Feature flags: evaluation order, the epoch rule, and five traps

- **Date:** 2026-11-27
- **Author:** crew: Engineer (T-0052)
- **Type:** Design record / gotchas
- **Related:** T-0052, T-0039, F-0038, F-0051, plan 01 U09, U49 and §3.4

## Summary
`mc_feature_flags` (U09) gives bricks typed flags and experiments that behave the same on every run, work offline from a cache, and never make boot wait for the network. `mc_fixtures_platform` (U49, flags slice) serves `GET /v1/flags` for it. The design is in the README of the package; this file records the decisions a reviewer would otherwise have to rediscover, and the traps.

## Decisions
1. **The order is literal.** Override, then the remote value of this epoch, then the last-known-good (LKG) for the same user while no fetch has succeeded in this epoch, then the default. A source with no value, or a value of the wrong type, falls to the next one. Because a successful fetch ends the LKG, a key the server omits, or sends with the wrong type, is the **default**, never an older value (the cache holds the same bad value anyway: the body is cached as received).
2. **One epoch check, after the await and before any write.** `_runFetch` reads `session.epoch` and `userId` before the request; after the `await` it returns if the epoch moved (or the object was disposed) and only then applies the result and writes the cache. The write is called with no await in between, and `FileStore` serialises writes of one key in call order, so a stale write can never land after a newer one. The race tests hold the **response** (the backend answers at once, so the body is the one for the user the request was sent as, and the test releases it): both orders for a user switch, and for a sign-out.
3. **The epoch is observed lazily as well as by the stream.** `Session.signIn` as the *same* user starts a new epoch but publishes no `authState` event (it is "not a change of user"). Listening to `authState` alone would miss it. `value`, `variant`, `refresh` and `start` call `_observeEpoch()` first. The old values stay as LKG for the same user (no flicker); for another user they are dropped at once (they are not that user's flags). A same-user sign-in's refetch therefore starts at the next read. This stays inside the package; adding an epoch stream to `mc_session` was out of scope.
4. **LKG is one slot, scoped to a user.** The cache is `{"userId", "body"}`; at open it is used only if `userId` equals the restored session's user. One slot means a user switch cannot use the previous user's cache and, after A, then anonymous, then A again, A starts from defaults until the first fetch. A slot per user would fix that and grow without bound; left for when there is a reason.
5. **`refresh()` joins an in-flight fetch of the same epoch** (one request for N callers); it may therefore return a result whose request started before the call. A different epoch never joins.
6. **Bucketing.** FNV-1a 32 over UTF-8 `"<experimentKey>:<subject>"` modulo 10000. The product is split as `(h << 24) + h * 403` (the prime is `2^24 + 403`), so no intermediate exceeds 2^41 and the result is the same on the VM and in JavaScript. A variant wins when `bucket < cumulative * 10000 ~/ total`; the test's independent oracle uses `(bucket + 1) * total <= cumulative * 10000` (the same rule written differently) with BigInt FNV, and the 28 golden rows are literals computed by a third implementation (Python). Sequential ids (`user-1`...), `u-100`... and random ids all split within 2 % of the weights for every fixture experiment.
7. **Remote weights are keyed by variant name.** A declared variant the remote entry omits has weight 0; a remote variant that is not declared is dropped. An entry with a malformed variant, or with no positive weight for any declared variant, is ignored (declared weights apply) and reported once. The first declared variant is the control, used when no weight is positive.
8. **Overrides fail closed.** `isReleaseLikeEnv(env)` is true for everything except `dev`, `e2e`, `perf` and `test`, so a typo or a new env name rejects overrides. Rejected calls return a `FlagOverrideFailure` (no throw). The saved file is not read in a release-like env (and `value` checks the env as well: two guards; a mutation of either alone is equivalent, so the tests pin the getter they share).
9. **Boot.** `FeatureFlagsDIInitializer` reads files only if they exist (`existsSync`, as `SessionDIInitializer`), registers, then calls `start()` without awaiting. The app-level test holds the `/v1/flags` response on a completer and asserts home is on screen and `diContainer<FeatureFlagsReader>().value(...)` is the default; a second test boots with `platform.server_error` and still reaches home.
10. **The install id is made lazily** (first anonymous `variant()`), kept in memory at once, and saved with an un-awaited write. If that write fails the id changes on the next launch; accepted.

## Traps
1. **Never `await` a `StreamSubscription.cancel()` in code a widget test may run under fake async.** `dispose()` first awaited `_authSubscription.cancel()`. A cancelled broadcast subscription returns a future created in the root zone; awaited from the fake-async zone it never completes during `pump`, so `staged.reset()` in `initializeDIContainer`'s failure path hung and 14 boot tests failed with "resetDIContainer() was called while initializeDIContainer is running". `dispose()` now fires `cancel()` and `close()` and returns a completed future. (Same family as the comment in `Session`: a future made at boot under fake async.)
2. **A Dio request at boot leaves a zero timer.** Dio starts a request on `Future(...)`, a zero-duration `Timer`. Two existing `boot_test` widget tests ended right after `pump()` with that timer pending ("A Timer is still pending"). `pump()` with no duration does not fire it (the timer is made during the pump); `pump(const Duration(milliseconds: 10))` does. Each of the two tests now ends with that pump (declared in the handoff; no assertion was removed). Any widget test that boots the real root list must do the same.
3. **The root list's traffic log has a new first entry.** `boot_test` asserted `recentTraffic` has length 1 after its probe request; the flags fetch is now recorded too. The assertion counts the probe's path instead (still exactly one).
4. **Mutation scripts and analyzer errors.** As F-0051: the Bazel build analyses with the repo lints, so a mutant that leaves a field unused (`unused_field`) or adds a style issue is *broken*, not killed. Write mutants so that every name stays used.
5. **`Enum.values` is a const list**, so `const EnumFlagCodec<Layout>(Layout.values)` works in a `const FeatureFlag`. `FeatureFlag<T>` has no named constructors per type (`.bool(...)`): a const constructor cannot narrow `T`, so the flag names its codec (`codec: BoolFlagCodec()`).
