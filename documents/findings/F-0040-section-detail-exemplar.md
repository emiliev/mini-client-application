# F-0040: The section/detail exemplar: a kit gap in date formatting, sociable tests of an auth-gated write, and what the BDD steps have to know

- **Date:** 2026-11-26
- **Author:** crew: Engineer (T-0041)
- **Type:** Lesson / library behaviour
- **Related:** T-0041, P1-18, F-0031, F-0033, F-0038, F-0039, plan 01 §3.3, §3.4, §4.2, R15, R17, R30, ADR-0010

## Summary
`comics_details` is the second exemplar (SC): one comic in sections, with a favourite that asks the app to sign in. **No codegen shim failed on a real-world case**; all 12 freezed, json, retrofit and injectable outputs and the 3 gen-l10n files equal build_runner's or the CLI's. One kit gap needed a marked workaround until the review round: `mc_formatters` needs its date symbols loaded, and no root initializer loaded them (fact 1; now a root initializer, fact 14). The rest are facts the bricks and their tests need: how to test an awaited `requestSignIn()` under fake async, how to prove a request carried the bearer, why sections below the fold are not in the tree, and a `$` in a Gherkin string.

## Facts
1. **Kit gap: nothing loaded the date symbols. Resolved in the review round (TL decision): see fact 14.** `formatDate(date, 'de')` throws `LocaleDataException` until `initializeFormatters()` ran. Plan 01 §3.4's root list has `L10nCoreDIInitializer`, which does not exist (`app_core` says so), and `McTestContainer` mirrors the root list, so neither the app nor the tests load them. `ComicsDetailsDIInitializer._init` awaits `initializeFormatters()` before `getIt.init`, marked `WORKAROUND (F-0040 fact 1)`. It is idempotent and synchronous in effect (intl's `initializeDateFormatting` fills its maps and returns `Future.value()`). **TL decision:** a root `FormattersDIInitializer` (or the planned `L10nCoreDIInitializer`) in `rootInitializers` and `McTestContainer`, or a self-initialising `mc_formatters`; then the feature's initializer goes back to Tide's verbatim shape. Neither package was T-0041's to edit.
2. **Codegen: real cases the shims handled with no change.**
   - retrofit: `@Path` parameters, `PUT` and `DELETE`, five endpoints on one API, a DTO file with eight `@Freezed(fromJson: true, toJson: true)` classes (nested objects, `List<int>`, lists of objects, `explicitToJson`);
   - injectable: a six-parameter bloc constructor whose root types (`SessionReader`, `EventBus`) come from two other packages, and an init file that imports a third package (`init_deps` gains `mc_formatters`);
   - freezed: a union case with a positional `ApiFailure`, a required named field and a `@Default`, `@Implements<McFailureState>()` on two cases of one union, and a flow state holding a same-package freezed type (deep `copyWith` compiles, as F-0031 fact 10 said);
   - go_router_builder: two route libraries in one wiring, each with its own `$appRoutes` (they are separate libraries, so the names never meet; each library wraps its list in a getter);
   - a bloc body edit re-runs only that bloc's freezed action and the injectable shards; the aggregate is a cache hit and retrofit and json do not run (`T-0041-AC7_cutoff.md`).
3. **Testing an awaited `requestSignIn()` under fake async.** Signing in writes the session to a real file, which a `testWidgets` body cannot await (F-0038 fact 1). The navigator mock therefore answers `requestSignIn()` with a pending `Completer`; the step `signing in succeeds as {...}` signs the fixture user in through the real `AuthApi` inside `tester.runAsync`, then completes it with true. While the completer is pending a scenario can assert that the feature waits (no request, the toggle disabled). The wiring's own sheet test alternates `runAsync(delay)` and `pumpAndSettle` until the sheet closes (`_settleRealIo`).
4. **Proving "the PUT carried the bearer".** The harness's `RecordedRequest` has no headers and the backend's `TrafficEntry` neither. The feature's test env appends a recording `Interceptor` to the shared `Dio` after the container is built; it runs after the auth interceptor, so it sees the request as the backend gets it, and it changes nothing. The step `the app sent {route} with the bearer of {user}` checks every such request carries the session's own token, of that user's fixture shape. The generic step `the backend answered {route} with {200}` reads the engine's traffic log: the favourites routes answer 401 without a valid bearer, so a 200 is a second, independent proof. A `headers` field on `RecordedRequest` (mc_test_utils) would make the recorder unnecessary (follow-up).
5. **A hold before the page settles starves it.** With a `the backend holds {...}` active, `mcSettle` pumps two frames instead of settling. A hold set before `I open comic` left the favourite's `GET` unanswered, so the first tap was ignored (the toggle was still loading). Set holds after the page has settled.
6. **Sections below the fold are not in the tree.** `ListView(children: [...])` builds its children lazily, like a builder. The cast row sits about 1,100 px down, so a step that asserts it must scroll first (`scrollComicUntilVisible`). A card in a horizontal row inside it may still be half off screen: `ensureVisible` before a tap.
7. **A `$` in a Gherkin string literal is Dart interpolation.** The BDD generator copies `{'...'}` into a Dart single-quoted string, so `{'$3.99'}` would not compile. Write `{'\$3.99'}`.
8. **intl puts a non-breaking space in German prices.** `formatMoney(Money(399, usd), 'de')` is `3,99 $`. The fact step compares with non-breaking and narrow spaces read as plain spaces, so the feature file can say `{'3,99 \$'}`.
9. **The retry interceptor retries a `PUT`.** It is idempotent, so a failing favourite write is sent three times (the client's own retries, `retryDelay` zero in tests). "A double tap sends one request" is therefore asserted on the successful path.
10. **The detail had only character ids. Resolved in the review round: see fact 15.** `GET /v1/comics/:id` lists `characterIds`, not names or art, so the cast section fetches `GET /v1/characters/:id` for each (1 to 6 requests, in parallel). A member the backend no longer knows (`404`) is left out; any other failure fails the page, and Retry reloads it. An embedded cast summary in the comics contract would save those requests (TL / contract decision).
11. **Shared names across wirings: the convention is a group prefix (TL decision).** The app imports every wiring's barrel side by side, so two wirings exporting `RouteTargets` would be ambiguous as soon as something names it. Every wiring names its targets for its group: `UniverseRouteTargets` (renamed in the review round), `PublishingRouteTargets`, and the bricks emit `<Group>RouteTargets` / `<Group>RouteTargetsImpl`. **`mc_arch_check` only checked a class named exactly `RouteTargets`**, so a prefixed class escaped R15's "returns a `*Flow`" rule; it now checks every class whose name ends in `RouteTargets` (fixture `GroupRouteTargets`, test `T-0041-AC7 a group-prefixed RouteTargets class is checked too`).
12. **Plain `testWidgets` runs on an 800 x 600 surface.** The app-level test (`mini_client:comic_route_test`) sets `mcReferenceSurface`, as `mcTestWidgets` does; otherwise a tap at y = 616 misses with only a warning.
13. **A DS widget under a bare `MaterialApp` asserts.** `McButton` reads `McThemeExtension`; the wiring's sheet test builds `MaterialApp.router(theme: McTheme.of(...))`.

## Review round (TL decisions and `/code-review`)
14. **Formatters load at the root.** `mc_formatters` gains `FormattersDIInitializer` (it only awaits `initializeFormatters()`). It sits in `app_core`'s `rootInitializers` after api auth and before the wirings, where plan 01 has `L10nCoreDIInitializer`, and in `McTestContainer` (9 initializers now). The feature's initializer is back in Tide's shape. Proof: own-process tests (`mc_formatters:formatters_di_initializer_test`, `app_core:formatters_root_test`) first see `formatDate(..., 'de')` throw ("Locale data has not been initialized"), then boot the list and get `10. Jan. 1988`; intl's locale data is process-wide, so each needs its own target. `LocaleDataException` is not exported by `package:intl/intl.dart`, so the tests match the message. **Correction to fact 1:** Flutter's `GlobalMaterialLocalizations` loads intl's date data for every locale it supports when it loads (`loadDateIntlDataIfNotLoaded`), so under a `MaterialApp` with those delegates (the app, `McTestApp`) German dates already worked; fact 1's "throws" held only in a process with no such tree. The root initializer is still right: it covers formatting outside a widget tree (pure Dart, before the first frame) and does not depend on which delegates an app installs. That is also why the mutation "the test container does not load the formatters" survived the BDD suite; `mc_test_utils:formatters_container_test` (no widget tree, its own process) kills it.
15. **The comic detail carries its cast.** `GET /v1/comics/:id` adds `characters: [{id, name, thumbnail}]`, in `characterIds` order; `characterIds` stays (T-0038's tests, the `characterId=` reverse lookup and its contract read it). The summary is built from `mc_fixtures_characters`' own universe for the backend's seed, so it cannot drift. That package used `mc_fixtures_media` only for the art-set size (24) and the `ApiImage` re-export; it now uses `mc_media` and a constant `characterArtCount`, checked against `placeholderSets['characters']`, which makes it **pure Dart** and lets `mc_fixtures_comics` depend on it (`tool/checks/T-0041-AC1_fixtures_closure.sh`; T-0038-AC4's positive control moved to `mc_fixtures_media`). A provider-contract test compares every served summary with `GET /v1/characters/:id`, for seeds 42 and 7. The page makes one request; the feature tests no longer serve the characters domain, so the strict harness would fail any per-character request.
16. **Non-numeric ids never reached an ErrorWidget.** Every typed route gets a route-level `redirect` that calls the generated factory first, and go_router 17.5 turns an exception there (`int.parse` of `abc`) into its error match list, so `/comics/abc` and `/creators/1x` already showed the app's `errorBuilder` (`NotFoundPage`). A route `redirect` with `int.tryParse` could not run before that factory anyway. Pinned instead: wiring tests for both routes, app tests for a running-app link and a cold-start link, and the e2e (`20_bad_comic_link_not_found.png`).
17. **A sheet closed mid sign-in.** The fixture sheet now refuses Back and the barrier while signing in (`PopScope(canPop: !_busy)`), and `showFixtureSignInSheet` answers the real outcome however it closes: a sheet popped without an answer (a drag, a route change) awaits the sign-in it started.
18. **The favourite follows the session.** The bloc listens to `SessionReader.authState`: a sign-in elsewhere reloads the flag for that user, a sign-out (a rejected refresh included) shows "not a favourite". It records the session epoch its state belongs to, so its own tap's sign-in does not trigger a second read, and a change during a tap is applied when the tap settles. After `requestSignIn()` returns true it reads the flag for the new session first: a user who already has the comic gets no write. A new `signingIn` state replaces `ready(saving: true)` during the sign-in.
19. **`RecordedRequest.headers`.** The harness records each request's headers as the adapter sees them, after every interceptor, so the generic step `the backend received {route} with the bearer of {user}` replaces the feature's recording interceptor.
20. **A rejected refresh in a widget test needs real time.** The auth interceptor awaits the session's sign-out, a real file write; the generic step `the app finishes writing to storage` alternates `runAsync` and pumps so the write, and the failed request after it, complete.
