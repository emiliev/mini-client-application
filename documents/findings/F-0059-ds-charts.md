# F-0059: DS charts: testing painters, per-datum semantics, theme-lerp traps and label overlap

- **Date:** 2026-11-27
- **Author:** crew: Engineer (T-0059)
- **Type:** Gotcha and design notes
- **Related:** T-0059-AC1 to AC5, F-0014 (goldens), F-0043 (DS kit gotchas), [evidence](../evidence/T-0059/engineer/)

## Facts
1. **A recording canvas is a 40-line class.** `class RecordingCanvas implements Canvas` with a `noSuchMethod` that stores `(name, positionalArguments)` is enough to assert every `drawRect`, `drawLine`, `drawArc`, `drawCircle`, `drawPath` and `drawParagraph` a painter makes (`test/support/recording_canvas.dart`). `TextPainter.paint` ends in one `drawParagraph(paragraph, offset)`, and `paragraph.longestLine` gives the drawn width, so label overlap and clipping are testable without pixels. Shared test helpers need `srcs = glob(["test/support/*.dart"])` on the `flutter_test` target.
2. **`Paint.color` does not round-trip.** `Paint()..color = c` stores 8-bit channels, so `paint.color == c` is false for the same colour (the float channels differ in the last bits; the failure message shows two identical-looking colours). Compare `toARGB32()`.
3. **Per-datum semantics: `CustomPainter.semanticsBuilder`.** It returns `CustomPainterSemantics(rect, properties: SemanticsProperties(label, sortKey: OrdinalSortKey(i)))`, one per datum, in data order. The painter is wrapped in `Semantics(container: true, explicitChildNodes: true, label: summary)`, so the summary stays a node of its own and the data nodes are its children. `tester.semantics.simulatedAccessibilityTraversal()` returns the nodes in VoiceOver order; the tests assert that order, including a chart whose data order differs from its visual order. The legend and the donut's centre text are wrapped in `ExcludeSemantics` (the nodes already say it). `meetsGuideline(textContrastGuideline | labeledTapTargetGuideline | iOSTapTargetGuideline)` passes on every chart in all 4 themes. Painted tick and category labels are not nodes.
4. **`McThemeExtension` has no `==`.** A new `ThemeData` on every `pumpWidget` is never equal to the old one, so `AnimatedTheme` starts a 200 ms lerp. Symptoms: `transientCallbackCount == 1` for no visible reason, and a chart painted with the previous variant's colours right after a variant switch. In tests, build one `ThemeData` per variant once (`_themes`), and `pumpAndSettle()` after changing variant.
5. **`mc_test_utils` cannot be loaded by plain `fvm flutter test`**: it pulls in `mc_api_client`, whose `.g.dart` only exists under Bazel. `charts_test.dart`, `painter_test.dart` and `geometry_test.dart` therefore use only `mc_ds_theme` and `flutter_test`, and run in 3 s with `fvm flutter test utility/mc_ds_charts/test/...`; only `golden_test.dart` uses `mcGoldenMatrix`.
6. **Clamping an edge label into the canvas moves it onto its neighbour.** With 30 bars at 2x text the last label was clamped left and touched the one before it ("Tag 19Tag 28"). Labels that do not fit are now skipped, and the stride adds 8 pt of padding. A painter test checks, at 1x, 2x and 3x, that drawn category labels neither overlap nor leave the canvas.
7. **Tick rule.** `mcNiceStep` rounds the raw step *up* to 1, 2, 5 or 10 times a power of ten, so an axis never has more ticks than asked for (`0..100` gives `0, 50, 100`). The first and last tick are then pushed outwards to a multiple of the step, so a single value can yield one tick more than the target. The tick count follows the room on the axis, clamped to 3..6 (a minimum of 2 gave `-100..100` for data in `-30..60` on a narrow horizontal chart at 2x).
8. **Donut minimum sweep** (`mcDonutSweeps`): a positive value is raised to the minimum (default 4 degrees) and the others give way in proportion. Raising one can push another under, so the pass repeats until stable. If `positives x minimum >= 360 degrees` the segments share the turn equally. Zero stays zero, all-zero gives all zero. The drawn arc therefore overstates a tiny value slightly; the legend and the semantics carry the exact number. The ring has a 1 degree gap between segments (only when more than one segment is drawn and the sweep is more than twice the gap); the gap is drawn, the sweeps are not shortened, so the sum stays exact.
9. **Contrast baseline is `surface`.** Every series and role colour has at least 3:1 against `McPalette.surface` in all 4 themes. `neutral` (alias of `outline`, `8E8E98`) is 3.2:1 on the light `surface` but about 2.9:1 on the light `background`: charts belong on cards (`surface`), and the goldens draw them there.
10. **Shape as well as colour.** Line series differ by marker (circle, square, triangle) and by legend entry; donut and radar have a legend with the value; bars carry the labels. The three series colours differ in hue.
11. **Change detection by value.** Parents rebuild with new list instances, so the data classes have `==`, charts compare lists with `listEquals` (NaN equal to NaN in `mcSameDoubles`), and only a real change re-validates, restarts the animation and reports again. A mutation that restarts on every update is killed by a test.
12. **Reduced motion.** `animate: true` is ignored when `MediaQuery.disableAnimations` is set; while a donut draws in, an empty track ring is drawn under it.

## Implications
- New colour roles live in `McPalette` (`series1..3`) with `positive`, `negative` and `neutral` as getters on existing colours: no existing pixel changed (the gates diff every other package's goldens against `origin/main`).
- Bricks that show scores (`trivia_quiz`), stats (`characters_powers`) or history (`characters_timeline`) pass a localised summary label, a localised empty message and, if needed, a `valueFormatter`; the DS has no l10n.
- The release-mode path is tested through `McChartValidation.releaseModeOverride` and `reporterOverride` (both `@visibleForTesting`).
