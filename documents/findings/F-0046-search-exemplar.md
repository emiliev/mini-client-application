# F-0046: The search exemplar: races under fake time, real storage I/O in widget tests, and what DebouncedQuery does and does not do

- **Date:** 2026-11-26
- **Author:** crew: Engineer (T-0046)
- **Type:** Lesson / library behaviour
- **Related:** T-0046, P1-19, F-0024, F-0031, F-0038, F-0040, F-0043, plan 01 §3.3, R15, R17, R30, ADR-0010

## Summary
`discovery_search` is the third exemplar (SR): a debounced search over characters and comics, grouped results with type chips, and recent searches on `mc_storage`. **No codegen shim failed on a real-world case**: all 11 freezed, json, retrofit and injectable outputs equal build_runner's, and the 3 gen-l10n files equal the CLI's after `dart format`. What the bricks and their tests need to know is mostly about time: how to drive a debounce and out-of-order answers deterministically, and why real file I/O needs many rounds of real time inside a `testWidgets` body.

## Facts
1. **Codegen: new real cases the shims handled with no change.**
   - injectable: an `@module` with a `@lazySingleton` method whose parameter is a root type (`SearchHistory searchHistory(FileStore store)`), next to a retrofit `@factoryMethod`, a repository and a five-parameter bloc;
   - freezed: a sealed union with **public** case classes (`SearchHit.character = CharacterHit`, `.comic = ComicHit`) matched with `switch` patterns, a domain model with a private constructor and a getter (`const SearchResults._()`), and `@JsonSerializable(explicitToJson: true, includeIfNull: false)` on a freezed factory (an absent `subtitle` round-trips);
   - retrofit: a nullable named `@Query` (`limit`);
   - go_router_builder: an optional query parameter (`SearchRoute({this.q})`); its `location` equals `Uri(path:, queryParameters:).toString()` for spaces, `&`, `#` and non-ASCII (the wiring's drift test pins five cases).
2. **Real file I/O is one hop per `dart:io` call under fake time.** A `testWidgets` body runs on fake time; a real read or write completes only during `tester.runAsync`, and the code that awaited it runs only on the next `pump` (its continuation is a microtask of the fake zone). That code may start the next call, so a chain of calls needs one `runAsync` + `pump` round per call. One `SearchHistory.add` is a read, a directory create, a write with flush and a rename (about 10 hops); the generic step `the app finishes writing to storage` did 10 fixed rounds, so two queued saves left the second one unwritten (the first BDD run of "The recent searches survive a new search flow" read `['amber']` instead of `['spi', 'amber']`). The step now runs the same 10 rounds and then 2 ms rounds until the session's storage directory (names, sizes, modification times) is unchanged for 25 rounds (`mcFinishStorageIo`, `mc_test_steps`); it fails after 1,000 rounds of change. A pure read changes nothing on disk, so the first 10 rounds still cover it.
3. **Storage that cannot be written, in a test.** `the app can no longer write to storage` replaces the session's storage directory with a plain file: every `FileStore` call then fails (`Not a directory`), which is how the "a failed save keeps the list" branch is tested. The file is removed in a tear-down (the session deletes only a directory).
4. **Holds can be per query.** `the backend holds {'GET /v1/search?q=spire'}` holds only requests whose `q` is `spire` (the harness matches each query key by equality), so two searches can be answered in either order: "a slow answer for an older query" and "answers in reverse order" are deterministic scenarios with `the app sends` and `the backend releases`.
5. **Fake time for a debounce.** `I type {'spi'} one character at a time` (generic) enters "s", "sp", "spi" 100 ms of fake time apart and does not settle; `{299} milliseconds pass` then `{1} milliseconds pass` pins the 300 ms boundary (a 200 ms debounce and no debounce are both killed mutations). `mcSettle` itself runs 500 ms first, so any step that settles fires the debounce.
6. **What `DebouncedQuery` does not do, and how the bloc copes.** `onClear` fires only when the field empties after a search *fired*; there is no "search now". The bloc therefore starts `idle`, so every other state comes from a fired search and `onClear` covers every way back to the recent searches (the clear button, select-and-delete, a clear during the debounce of a later edit). A tapped recent search and a flow's initial query (`/search?q=`) go through `update` too and are searched 300 ms later: searching them directly would leave `DebouncedQuery`'s last query stale, and a later edit back to that stale text would be dropped as "unchanged". A `DebouncedQuery.submit(text)` (search now, and remember it) would remove the delay; that is `mc_paging`'s to add (follow-up for the TL).
7. **The latest query wins by generation, not by cancellation.** Every search, clear and too-short query bumps a counter; an answer is shown only if its counter is still current. Stale requests are not cancelled (the backend is in-process); a `CancelToken` would save work on a real network but could not replace the check, because a cancel can lose the race with an answer already delivered.
8. **Lazy lists in steps.** `ListView(children: [...])` builds only what is near the screen, so the "Showing 20 of 400" note under 20 rows was not in the tree. Steps that assert a whole section collect the rows while scrolling from top to bottom (`shownResults`), and `I scroll the results to the end` comes before a check of the end. On the simulator the keyboard halves the viewport the same way: the e2e unfocuses the field and waits before it looks for the second section.
9. **A focused field's caret blinks in a golden.** The search page autofocuses its field, and the caret's blink is timer-driven, so a golden could depend on fake time. The golden test sets `EditableText.debugDeterministicCursor = true` (a steady caret) and resets it in `tearDown`.
10. **`bazel test` and `bazel build` of a `flutter_library` do not run the analyzer over it; `--config=lint` and `bazel coverage` do.** An unused import and an `unawaited_futures` info in the feature passed every test target and failed only the coverage run. Run `build --config=lint` on the package early.
11. **A mutation script must not use `HOME` as a variable.** The first mutation run set `HOME=app/mini_client/...`, so `fvm` and Bazel failed in every mutation and the script reported all 46 as "survived". The variable is renamed, and a target that fails without a failing test, a run in which no test passed and a failed `dart format` are now reported as "not evidence" instead of a verdict.

## Implications / actions
- Bricks: per-query holds and the typing and time steps for every debounced feature (facts 4, 5); generation counters for "the latest query wins" (fact 7); idle as the initial state when the kit's clear signal follows a fired search (fact 6); `debugDeterministicCursor` in goldens of focused fields (fact 9).
- TL decisions: `DebouncedQuery.submit` in `mc_paging` (fact 6); whether the UI should use `GET /v1/search/suggestions` (the API declares it; see T-0046 Outcome).
- Any test that saves to `mc_storage` uses `the app finishes writing to storage` (fact 2), now safe for queues of writes.
