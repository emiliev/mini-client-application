# F-0058: DS overlays: what the framework does to dialogs, sheets, menus and toasts at large text and under test

- **Date:** 2026-11-27
- **Author:** crew: Engineer (T-0058)
- **Type:** Gotcha
- **Related:** T-0058-AC1 to AC4, F-0043 (intrinsic sizing), F-0014 (goldens under Bazel), T-0039 / T-0041 / T-0048 (the sign-in sheet)

## Facts
1. **`AlertDialog` does not name its route on iOS.** Its `semanticLabel` is only filled for the other platforms, so VoiceOver would not announce the title. `McDialog` is a plain `Dialog` with `Semantics(scopesRoute: true, namesRoute: true, label: title)`. The test reads `flagsCollection.namesRoute` and `scopesRoute` off the semantics node.
2. **`SnackBarAction` overflows at large text.** The action sits in a `Row` as a non-flex child, so "Rückgängig machen" at 2x is wider than the screen (overflow by 199 px). `showMcToast` puts the message and its own `TextButton` in a `Wrap`: they share a line when they fit and the action drops to its own line when they do not.
3. **A snack bar with an action never closes by itself.** `SnackBar.persist` defaults to `action != null`. The toast passes `persist: false`, so the "longer with an action" duration (8 s against 4 s) is real.
4. **A second toast needs `removeCurrentSnackBar()`.** `showSnackBar` queues behind the current one; `hideCurrentSnackBar()` still keeps the first one on screen while it animates out. `removeCurrentSnackBar()` replaces it in the next frame.
5. **`PopupMenuButton` names itself through `tooltip` only.** Its semantics node has an empty `label` and a `tooltip`, so `labeledTapTargetGuideline` is satisfied but a screen reader gets a hint, not a name. `McMenuButton` wraps it in one `Semantics(label, button, onTap: showButtonMenu)` with `excludeSemantics` (as `McIconButton` does), passes `tooltip: ''` to the popup button, and draws the hover tooltip with its own `Tooltip`.
6. **`Navigator.pop` ignores `PopScope`; `maybePop` honours it.** The sheet's drag handle (a dismiss button for screen readers) calls `maybePop`, so the sign-in sheet that is busy (`PopScope(canPop: false)`) is not closed by it.
7. **A sheet title must scroll with its body.** With the title outside the scroll view, a long title at 3x pushed the column past the sheet's maximum height (overflow). Handle fixed, title and body in one `SingleChildScrollView`.
8. **`showModalBottomSheet` needs `isScrollControlled: true` for a tall sheet.** Without it the sheet is capped at 9/16 of the screen, which at 3x text hides most of the body. `useSafeArea: true` keeps it below the status bar.
9. **The test binding draws shadows as hard black outlines** (`debugDisableShadows` is true), so a sheet or a menu golden shows a thick black ring. The golden test sets it to false for its own frame and restores it in a `finally`, before the test binding checks its invariants (a `tearDown` is too late: the invariant check fails the test). `mcGoldenMatrix` has no hook for this, so `golden_test.dart` carries a small local copy of it.
10. **The brand's primary colour is itself red** (`0xFFB3131B` against the error `0xFFB00020`), so a filled destructive button next to a filled primary one is not distinguishable. A destructive action is **outlined** in the error colour (2 px) and the primary is filled.
11. **In `flutter_test` 3.47 `tester.binding.rootPipelineOwner.semanticsOwner` is null.** Walk the semantics tree from `tester.binding.renderViews.first.owner!.semanticsOwner!.rootSemanticsNode!`; `pipelineOwner` still works but is deprecated.
12. **`mc_test_utils` does not compile under plain `flutter test`** (it reaches `mc_api_client`, whose `.g.dart` is generated by the Bazel overlay). Run overlay tests and update goldens with Bazel: `tool/bazelw run //utility/mc_ds_overlays:golden_test -- --update-goldens` (F-0014).
13. **`Wrap`, `SizedBox` and a `ColoredBox` target.** A `SizedBox` has no hit-test area of its own, so `tester.longPress` on it warns "would not hit test"; the tooltip test's target is a `ColoredBox`.
14. **A sheet's dismiss label must be on two nodes.** The barrier (`ModalBarrier.semanticsLabel`, set through `barrierLabel`) and the handle (a button with a tap action). The first is what a screen reader reads for "tap outside to close", the second is what it can activate.
15. **`PopupMenuItem` keeps a disabled row in the tree** with `enabled: false`; its semantics node has no tap action, and a tap on it leaves the menu open. A mutation that enables the row is killed by "a disabled item ignores taps and keeps the menu open".
16. **The `SnackBar` is a live region on its own** (`Semantics(container: true, liveRegion: true)` in its build), so a `Semantics(liveRegion: true)` around the message adds nothing; a mutation that removed it survived. The wrapper is gone and a test pins the framework's behaviour (a live-region node that holds the message).
17. **Material pads a button to 48 pt** (`MaterialTapTargetSize.padded`), so `minimumSize: Size(44, 44)` on a `TextButton` or `OutlinedButton` never decides the hit area, and a mutation to `Size.zero` is equivalent. The declared minimum stays for parity with `McButton`; the tap-target test would catch a switch to `shrinkWrap`.
18. **A test helper must not pass the default it tests.** The first `_confirm`, `_openChoice` and `_menuApp` helpers took `useRootNavigator = true` and passed it on, so four "default is nearest navigator" mutants survived. The helpers now pass the option only when a test sets it.
19. **A single `pump(Duration)` hides exit animations.** The first duration test pumped 6 s in one step: the 4 s timer fired but the toast was still in the tree (its exit animation had just begun), so a mutant that dropped the longer action duration survived. Pump past the timer, then past the animation, then assert.
