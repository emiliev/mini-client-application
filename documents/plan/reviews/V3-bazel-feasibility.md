# V3: Bazel feasibility audit (plan 03 + README R8 to R12, R14, R15, R18, R19, R28 + 04 §3 to §8 + 05 §5 to §6 + ADR-0008)

_Verifier V3, 2026-11-23. Independent of the planners. I read the sources only and ran nothing from them._

**Sources.**
- `ai_rules_dart`: a shallow clone, HEAD `be4e99f`. The pin `e7163aab8f9171f54693cd1b99feb7d3cee9602d` **is in the clone**: it is the `v0.28.3` tag and sits 17 commits behind HEAD. Those 17 commits are CI and perf tooling only. All `rules_dart` refs below come from `git archive e7163aa`.
- `ai_rules_flutter`: HEAD = pin = `876e263` = `v0.30.2`.
- pub.dev API and raw GitHub, for generator pubspecs and imports. Each one is marked "(pub.dev)" or "(GitHub)".

Paths are relative to each repo root. `RD` is rules_dart; `RF` is rules_flutter.

## Verdict

**FEASIBLE WITH ISSUES.**

The pins, the extension tags, the Flutter 3.47.7 entry, the Apple rule versions, and every rule, macro, provider, flag and mnemonic the plan names all exist. The three fork shims are buildable on the `builder_shim` / `dart_codegen` / `dart_aggregate_codegen` APIs. The injectable version premise (X3) is correct, and better than the plan assumes.

I found nothing that blocks the plan outright. Several items will fail as written:
- an undefined `--config=lint`;
- an illegal `--nodisk_cache`;
- the dev tool's `-d <udid>`;
- the e2e journey filter sent over `SIMCTL_CHILD_`;
- the H-DI-CUTOFF acceptance criterion as wired.

One major risk is untested anywhere upstream: shim codegen over a closure that contains Flutter (go_router). The R28 fallback contradicts three other plan rules.

## Verified claims

1. **Pins.** `e7163aa` is `v0.28.3` (in the shallow clone). `876e263` is `v0.30.2`. RF builds against `e7163aa` (`MODULE.bazel:179-183`). Both repos are Bazel 9.3.0 (`.bazelversion`, `bazel_compatibility >=9.0.0`). Module names are `ai_rules_dart`/`ai_rules_flutter`, with `repo_name` `rules_dart`/`rules_flutter`.
2. **Apple rules.** rules_apple 5.2.0, rules_swift 4.1.2 and apple_support 2.9.1 are what `e2e/ios_example/MODULE.bazel` declares, and what RF's root pins (`MODULE.bazel:214-227`). Declaring them in our root makes MVS pick them over RF's floors (4.5.3 / 3.5.0 / 2.2.0). rules_cc 0.2.26, skylib 1.9.2 and platforms 1.1.0 match.
3. **Extension tags.** `flutter.toolchain(flutter_version)`, `flutter.pub(name, lock)`, `flutter.version` and `use_repo(… "flutter_ios_engine", "flutter_toolchains")` exist (RF `flutter/extensions.bzl:86-111, 847-853`; `e2e/ios_example/MODULE.bazel`). Flutter **3.47.7** is a stock entry (`flutter/private/versions.bzl:100`, with about 60 checksums at `:974`). 3.47.8 is absent (X7 correct). One Dart SDK, Flutter's, serves rules_dart (RF `README.md:2305`).
4. **Rules and symbols.** `dart_codegen`, `dart_aggregate_codegen` (with `asset_deps`), `dart_sqlcodegen` (any extension), `flutter_library`, `flutter_test`, `flutter_prebuilt_test` (`dill`/`base_dill`/`assets`, fed by the `test_kernel`/`test_base_kernel`/`test_assets` output groups; RF `flutter_test.bzl:448-460`), `flutter_application(min_os_version)`, `flutter_ios_app` (with `bundle_id`, `families`, `app_name`, `provisioning_profile`, `signing`), `flutter_ios_simulator_build_test`, `flutter_integration_test(platform, ios_bundle_id)` (with `exclusive` forced), `flutter_drive_test`, `flutter_gen_l10n` (with `arbs`, `template_arb_file`, `output_localization_file`, `output_class`, `nullable_getter`), `flutter_font_family`, `IOS_MINIMUM_OS_VERSION`, `@rules_flutter//flutter:material_icons` and `@rules_flutter//flutter:pub` all exist.
5. **Settings.** `--@rules_flutter//flutter:profile` (a bool flag applied with `-c opt`), `:incremental_kernel`, `:dev_incremental_serialization`, `:extra_dart_defines`, `--@rules_dart//dart:analysis_config`, and `//dart:analyzer_summaries` (default on, `dart/BUILD.bazel:119`) exist. The consumer preset is exactly `--reuse_sandbox_directories --nobuild_runfile_links --experimental_shrink_worker_pool` (`dart/consumer.bazelrc`).
6. **Mnemonics.** `DartCodegen`, `DartAggregateCodegen`, `DartSqlCodegen`, `DartKernel`, `DartKernelLink`, `DartAnalyze`, `DartAnalyzerSummary`, `DartImportCheck`, `FlutterKernelCompile` and `FlutterAotMacho` exist. `--worker_extra_flag=DartKernel=--phase-timing-log=` is a real startup flag (RD `dart/private/tools/kernel_module.dart:83-84`).
7. **Visibility.** `//dart/ext:builder_shim` is visible only to `//dart/ext:__subpackages__` (and tests) (RD `dart/ext/BUILD.bazel:40-52`), so fork shims must live under `dart/ext/`. Curated wrappers such as `shared_part_library` create their own `dart_library` (RD `dart/ext/_shared/defs.bzl:31-112`), so R8/KD5 is right.
8. **Ext lock** (`dart/ext/pubspec.lock`): analyzer 14.5.0, `_fe_analyzer_shared` 109.0.0, build 4.0.11, source_gen 4.3.1, freezed 4.0.2, freezed_annotation 3.1.0, json_serializable 6.14.1, json_annotation 4.12.0, go_router_builder 4.5.0, get_it 8.3.0, dart_style 3.1.14, code_builder 4.13.0, recase 4.1.0, glob 2.2.0, protobuf 6.1.0. `@ext_pub_deps` is `isolated = True`. KD4's annotation pins match.
9. **X3 premise (pub.dev / GitHub).** injectable_generator 3.1.3 requires analyzer `>=10 <15`, build `^4.0.4`, source_gen `^4.1.1` and lean_builder `^1.2.2`. lean_builder 1.2.2, the latest, caps `_fe_analyzer_shared <106`. So lean_builder is the *only* conflict. `builder.dart`, both generators, `dependency_resolver.dart` and `importable_type_resolver.dart` import no lean_builder. Vendoring without `lib/lean_builder/` is feasible, and it compiles against 14.5.0 within the declared range.
10. **retrofit_generator 10.3.3** (pub.dev): analyzer `<15`, build `<6`, source_gen `^4`, protobuf `^6`, dio `^5.9`, retrofit `^4.10`. Compatible. **bdd_widget_test 3.0.5**: build `^4`, no Flutter dependency, analyzer only as a dev dependency. Compatible.
11. **Shim mechanics.** Declared-but-unemitted outputs are written empty (`builder_shim.dart:985-1024`). `findAssets` covers the staged `--dep` assets and earlier-stage writes (`:1261-1268`). Outputs are routed by suffix, then by basename (`:1040-1060`).
12. **Summaries.** Off with a Flutter embedder (`sky_engine` or `_embedder.yaml`) in any dependency's closure (RD `dart_codegen.bzl:124-129`, `dart_analyzer_summary.bzl:120-137`). Off for non-shim generators (`:116-122`). Supported SDK range 3.13 to 3.14 (`dart_analyzer_summary.bzl:57,70`). KD6's line citation is accurate.
13. **iOS.** A simulator app is refused outside `-c dbg` (RF `flutter/ios.bzl:463-500`). `ios_sim_debug_app` sets `dbg` and `sim_arm64` (`ios_sim_debug.bzl:24-45`). Simulator `dbg` bundles skip codesign through `apple.skip_codesign_simulator_bundles` (`ios_app.bzl:391-399`, `README.md:686`). Device builds need `provisioning_profile` (X8 correct).
14. **Tests.** `--test_filter` (`TESTBRIDGE_TEST_ONLY`, `bazel_test_protocol.dart:75`) and `--test-randomize-ordering-seed=random` (`flutter_test_runner.dart:87-131`) are supported. `flutter_test_config.dart` isn't honoured, and the Bazel golden comparator is installed instead (`goldens/comparator.dart:17-22`).
15. **Path mapping.** Neither repo declares `supports-path-mapping` (X9 premise correct). `dart_codegen` has no `unused_inputs_list` (U-D7 premise correct).
16. **REPO.bazel.** `ignore_directories` is used by RD itself (`REPO.bazel`). The dev tool exists (`tools/dev_tool:flutter_bazel`, public), with `-t` and `-d kind:id`.
