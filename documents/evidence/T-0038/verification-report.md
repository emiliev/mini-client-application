The fact itself (offset 40 starts at `Amber Gambit #1`) is correct. Suggested wording: "Offset 40 (after Amber Chronicles and Amber Frontier)".

Release-date ties do exist (VP5 counts them), and VP5 kills M13. Suggest adding an assertion that adjacent equal dates are in ascending id order. The characters domain likely has the same gap for `modified`.

## Notes for the Tech Lead
4. **Error code differs between set and scenario.** The `comics.server_error` fixture set (`FailingComicsDomain`) answers `error.code: server_error` (`comics_handlers.dart:168-169`). The scenario of the same name answers `injected_failure`, like `characters.server_error` (VP9). It is documented (CONTRACT.md:114), and the characters domain has no `server_error` set to compare with. A feature test that asserts on the code would see different values depending on which one it uses. Other shapes agree with characters: the 400 bodies for a shared rule are byte-identical, the 404 key set is the same, and the raw id is echoed the same way (VP8). The comics `empty` scenario also 404s its detail routes, while `characters.empty` overrides only the list. That is stricter, not inconsistent.
5. **Trademark-adjacent words.** The series noun "Gambit" (and, to a lesser degree, "Vanguard" and "Legacy") is an ordinary English word that is also a Marvel character or imprint name. "Iron Legacy" may coincide with a minor Marvel character name (unconfirmed). No full title is a real Marvel title. The characters domain already sets this precedent (`Vanguard`, `Sentinel`, `Herald`). Swapping "Gambit" for another noun would be cheap, but it would change the snapshots and the CONTRACT facts (`Amber Gambit #1`).
6. **Dead vocabulary.** `creatorLastNames` has 10 entries, but only the first 5 are reachable (`universe.dart:158`, `c ~/ 12` is 0 to 4 for 60 creators). This is harmless.
7. **History.** The branch carries two WIP commits (`826895e`, `25c61d4`) under the final one. A `--no-ff` merge will put them on `main`'s history.
8. **Gate script environment.** In a fresh worktree with no `.dart_tool/package_config.json`, the script's `dart format` gate reports 27 files changed and FAILs, because without package resolution the formatter can't see the language version ([first run](verifier/AC4_gates_first_run_no_pub_get.md)). After `fvm flutter pub get --offline`, which changed no tracked file, the format gate and the whole script PASS. This is not a code defect; the gate scripts could check for a resolved package config first.
